# Специфікація моделі даних

## 1. Промпт для AI

> **Prompt:**
>
> Створи концептуальну ER-модель для системи бронювання столів та оренди настільних ігор у клубі.
>
> Всі ідентифікатори та зовнішні ключі повинні мати тип `UUID`.
>
> Не потрібно створювати окрему таблицю для зв'язку M:N, якщо цей зв'язок не має додаткових атрибутів.
>
> Потрібно описати такі сутності: User, Booking, GameTable, BoardGame, Review.
>
> Назви атрибутів у тексті та Mermaid-діаграмі повинні збігатися та бути записані в `snake_case`.

## 2. Критерії прийняття

* [AC-1] Всі первинні та зовнішні ключі мають тип `UUID`.
* [AC-2] Модель повинна відповідати нормальній формі 3NF.
* [AC-3] Зв'язок між `Booking` та `BoardGame` є M:N і не має окремої таблиці `booking_games`, тому що цей зв'язок не має власних атрибутів.
* [AC-4] Назви атрибутів у специфікації та діаграмі повинні бути однаковими та записані в `snake_case`.
* [AC-5] `Review` є окремою сутністю, тому що має власні атрибути: `rating`, `comment` та `created_at`.
* [AC-6] Поле `email` у `User` є унікальним.
* [AC-7] `total_price` у `Booking` зберігає загальну вартість конкретного бронювання на момент його оформлення.

## 3. Опис сутностей та атрибутів

### 3.1. User (Користувач)

Зберігає основну інформацію про користувача.

* `id`: UUID (PK) - унікальний ідентифікатор користувача.
* `full_name`: string - ім'я та прізвище користувача.
* `email`: string - електронна пошта користувача, яка повинна бути унікальною.
* `phone`: string - номер телефону користувача.
* `created_at`: datetime - дата створення акаунта.

### 3.2. GameTable (Ігровий стіл / зона)

Описує стіл або окрему ігрову зону в клубі.

* `id`: UUID (PK) - унікальний ідентифікатор столу або зони.
* `table_number`: integer - номер столу або зони.
* `zone_type`: string - тип зони, наприклад VIP, Standard або Console.
* `capacity`: integer - максимальна кількість людей.
* `hourly_rate`: decimal - ціна оренди столу або зони за одну годину.

### 3.3. BoardGame (Настільна гра)

Містить інформацію про настільні ігри, які можна вибрати під час бронювання.

* `id`: UUID (PK) - унікальний ідентифікатор гри.
* `title`: string - назва гри.
* `genre`: string - жанр гри.
* `min_players`: integer - мінімальна кількість гравців.
* `max_players`: integer - максимальна кількість гравців.

### 3.4. Booking (Бронювання)

Зберігає інформацію про бронювання столу або ігрової зони користувачем.

* `id`: UUID (PK) — унікальний ідентифікатор бронювання.
* `user_id`: UUID (FK) - посилання на користувача.
* `table_id`: UUID (FK) - посилання на заброньований стіл або зону.
* `start_time`: datetime - час початку бронювання.
* `end_time`: datetime - час закінчення бронювання.
* `total_price`: decimal - загальна вартість конкретного бронювання.
* `status`: string - поточний статус бронювання: `pending`, `confirmed` або `cancelled`.

`total_price` зберігається в `Booking`, оскільки це ціна конкретного бронювання на момент його оформлення. Якщо `hourly_rate` столу зміниться пізніше, вартість уже створеного бронювання не повинна змінюватися.

### 3.5. Review (Відгук)

Відгук користувача про стіл або ігрову зону.

* `id`: UUID (PK) - унікальний ідентифікатор відгуку.
* `user_id`: UUID (FK) - користувач, який залишив відгук.
* `table_id`: UUID (FK) - стіл або зона, про які залишено відгук.
* `rating`: integer - оцінка від 1 до 5.
* `comment`: string - текст відгуку.
* `created_at`: datetime — дата створення відгуку.

## 4. Зв'язки та кардинальності

* **User 1 : N Booking** - один користувач може мати декілька бронювань. У `Booking` для цього використовується `user_id`.
* **GameTable 1 : N Booking** - один стіл або зона може мати багато бронювань у різний час. У `Booking` використовується `table_id`.
* **Booking M : N BoardGame** - до одного бронювання можна додати декілька ігор, а одна гра може використовуватись у різних бронюваннях. Окрема сутність для цього зв'язку не створюється, оскільки він не має власних атрибутів.
* **User 1 : N Review** - один користувач може написати декілька відгуків.
* **GameTable 1 : N Review** - один стіл або зона може мати декілька відгуків.
